# 应用使用指南（audio-coupled-haptics app）

> 对应代码：`app/`。实现依据为 [实现规格书](haptic-playback-spec.md)，
> 本文件只讲「怎么用」以及「每个控件背后发生了什么」。

## 1. 首次使用流程

1. 打开应用，主控球显示「启动」。
2. 点击启动 → 应用先弹一段说明，然后系统依次要求两个授权：
   - **录音权限**（`RECORD_AUDIO`）；
   - **系统录制/投放授权**（MediaProjection）。
     Android 要求每次开始都确认一次，这是系统行为，不是应用重复索要。
3. 授权后前台服务启动，通知栏出现「音频耦合触觉 · 正在驱动马达」，可在此直接停止。
4. 打开任意音乐 / 视频 / 游戏，手机应在约 0.5~0.7 秒后开始跟随声音振动。

### 关于「为什么要点录制/投放」

Android 抓取**系统内部声音**只有一条合法路径：`MediaProjection` 授权 +
`AudioPlaybackCaptureConfiguration`。普通应用拿不到 `REMOTE_SUBMIX`（系统签名权限），
所以这个系统授权页无法绕过、也无法改名。

本应用**只读取声音**：代码里没有任何 `VirtualDisplay`、不读帧、不存画面、不上传。
在授权页里建议选「共享一个应用」并选中正在放歌的那个 App：

- 只录制它的声音，更省电；
- 屏幕上的其它内容（聊天、密码框）都不会进入授权范围。

系统状态栏会显示类似「屏幕共享中」的胶囊提示——这是 ROM 对 MediaProjection 会话的
统一提示，应用无法定制或关闭。

## 3. 参数怎么调（按问题找滑杆）

| 你听到 / 摸到的问题 | 调整 |
|---|---|
| 低音太轰、糊成一团 | 提高「高通截止」，或提高「高通阶数」，或降低「低频混回」 |
| 太脆、没有力度 | 降低「高通截止」，或提高「低频混回」 |
| 安静段落完全没有振动 | 降低「安静门槛」 |
| 震动偏弱 | 提高「震动强度」（默认 72%，最高 250%）；还想更猛就选「强节奏」预设（100%），或把「压缩阈值」调高到 0.5~0.6 让响段少被压 |
| 震动太强 / 手心发麻 | 降低「震动强度」（每 0.1 大约 1.5dB），或选「轻柔」预设（45%） |
| 响段刺耳、像打底 | 降低「震动强度」，或降低「压缩阈值」更早压缩，并确认「启用软削波」为开 |
| **马达高音破音 / 沙沙声** | 马达只能跟随谐振频率附近（LRA 约 150~200Hz）的内容，更高的频率它跟不上就打滑。最轻的改法是降低「软削波上限」（如 99%→70%），把削波产生的谐波压下去；要彻底消除就开启「谐振载波驱动」，或把「高频上限（低通）」调到 250~300Hz |
| 调小媒体音量后振动消失 | 打开「启用动态压缩」（让振动跟随相对能量而非绝对电平） |
| 振动断断续续 | 看「平均编码」是否接近「分片时长」：降低「编码质量」或提高「分片时长」，也可提高「起播预缓冲」 |
| 起播慢但更稳 | 提高「起播预缓冲」（会自动夹到播放队列上限内） |
| 振感比声音晚 / 早 | 调「震动对齐」：正值=振动更晚，负值=振动更早 |
| 有回声（原声 + 延迟声） | 打开「静音系统原声」；需要 root / Shizuku，否则自动降级（预期行为） |

预设按钮会一次写好整套互相自洽的参数（震动强度、安静门槛、高通、低频混回、压缩阈值与比）；
手动改其中任意一项后，徽标回落为「自定义」。

## 4. 为什么声音变小了

播放被路由到**内置听筒**（`USAGE_VOICE_COMMUNICATION` + `setCommunicationDevice`），
这是规格书决策 2：部分平台的音频 HAL 只在这条路径上才会把第 3 声道转发给马达。
因此外放音量偏小属正常现象；你听到的仍是系统原始播放声，
只有当「静音原声」生效时，才变成「只有振动」。

## 5. 状态与提示含义

| 徽章 | 含义 |
|---|---|
| 待机 | 引擎未运行 |
| 启动中 | 正在申请投影 / 初始化采集与编码 |
| 运行中 | 全链路工作，主控球随声音呼吸 |
| 异常 | 见底部日志第一行（如原生库加载失败、采集失败） |

底部日志中 `触觉播放=不支持` 表示该机型没有开放音频耦合触觉（能播不震），不是应用故障；
`静音原声=不可用（静音降级）` 表示拿不到特权 shell，会有回声。

## 6. 参数持久化

所有参数写入 `SharedPreferences`（`engine_settings_v1`），重启应用后沿用；
「恢复出厂默认参数」会清空并回到规格书 §13 的建议值。

## 7. 自检：用「触觉测试音」验证整条链路

规格书里最难验证的一步是「换一个 App 也能震」。为此仓库额外带了一个自检工具
`tonegen/`（包名 `com.gaolou.haptictone`），它用**前台媒体服务**播放一段
55Hz 鼓点 + 440/1200Hz 的测试音：

```bash
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ANDROID_HOME=/home/t/android-sdk \
/home/t/gradle-dist/gradle-8.7/bin/gradle :tonegen:assembleDebug
/home/t/android-sdk/platform-tools/adb install -r tonegen/build/outputs/apk/debug/tonegen-debug.apk
```

步骤：

1. 主应用点「启动」并完成录音 + 屏幕录制授权（状态徽章变「运行中」）。
2. 打开「触觉测试音」，它会立刻开始播放（通知栏可见，可后台继续）。
3. 切回主应用，此时底部日志的「输入电平 / 触觉峰值」应随鼓点起伏（约 40%/70% 量级），
   同时手机应该跟着鼓点振动。
4. 播放最多 120 秒自动停止；测试音 App 可直接卸载，不影响主应用。

为什么需要两个 App：Android 的 playback capture 只抓**其它应用**的声音，
同一个应用自己的播放不会被采集。测试音必须"住在另一个 UID 里"才有效。

如果输入电平有值但完全不振，按规格书 §12 排查「能播不震」那一行：
comment 标记、设备能力、听筒路由三项。

补充三条本机实测踩出来的必要条件（缺任一条都会「能播不震」）：

1. `AudioAttributes.setHapticChannelsMuted(false)` —— 默认值是「静音触觉声道」；
2. 听筒路由要**周期性强制下发**（`setCommunicationDevice` + `setPreferredDevice`），
   不能只在系统上报的通信设备变化时才调用；
3. `STREAM_VOICE_CALL` 音量不能停在最低档，应用会在运行时自动抬到 90% 并在停止时还原。

现在默认开启「只保留振动」：重放的可听声压到 -46dB，你听到的只有系统原声，
不会再和延迟约 600ms 的重放声叠成"发闷/卡顿"的听感。

## 8. 为什么现在默认开启「谐振载波驱动」

线性谐振马达（LRA）有自己的谐振频率，通常在 150~200Hz。**只有这个频段的内容能让振子
有效起振**；更高频的内容（人声、镲片、以及削波产生的谐波）马达跟不上，就会打滑、
发出"沙沙/嘶嘶"的破音。

所以触觉链路里加了两道处理，默认都开：

- **输出级低通（高频上限，默认 300Hz）**：放在削波**之后**——因为软削波本身会产生
  大量高频谐波，低通放前面是滤不掉的。
- **谐振载波驱动**：把音频的**包络**取出来，再乘上马达谐振频率（默认 160Hz）的正弦，
  重新合成驱动波形。这样不论原音频是什么频率，送到马达的永远是它能跟随的频段，
  破音从根上消失；而力度仍跟着音乐能量走（快起音 + 慢释放的包络跟随）。

关掉开关或把「高频上限」调高，就能听到"原汁原味"的宽频驱动——代价是高频内容多时
会重新出现破音。

## 9. 震动功率是怎么拉满的

决定"手感有多强"的有四层，缺一层都会觉得不够：

1. **震动强度（触觉总电平）**：默认 72%（比旧版 65% 略强，因为软削波归一化后同样电平的
   实际输出更大），最高可到 250%。
2. **软削波归一化**：规格书里的有理近似软削波在 `f = limit = 0.99` 时输出只有
   `0.773`，等于白丢 23% 的行程。实现里除以了同点参考值，现在 `limit` 处输出正好等于
   `limit`，峰值能到 99%。
3. **通话音量**：触觉流走 `USAGE_VOICE_COMMUNICATION`，音量由 `STREAM_VOICE_CALL`
   决定，现在是拉满到 `max`（停止时还原）。
4. **播放流音量**：每个 MediaPlayer 都 `setVolume(1f, 1f)`。

如果这样还嫌弱，可以再往上：选「强节奏」预设、把「压缩阈值」抬到 0.5~0.6
（响段少被压）、或者临时关掉「启用软削波」换成硬削波（更硬、谐波更多）。
